# FR-4.7

| ID | Requirement | |
|---|---|---|
| FR-4.7 | TOML's canonical form is a table's scalars first and sorted, then its sections sorted, and no indentation. A sub-table is a `[path]` section; **an array whose every item is a table is repeated `[[path]]` sections**, because TOML has no inline form for one, so that is the only spelling rather than a choice between two. Every other array is inline on one line, including an empty one, which is `[]` whatever it would have held. Scalars precede sections for correctness rather than layout: TOML binds a bare key to the most recent header, so a scalar written after a section would land inside it. **A null is refused rather than substituted**, because TOML cannot spell one and FR-4.1 says a value with no canonical form is refused rather than guessed at. **A structure that is not a table is refused**, because TOML has no top-level scalar or array. **A native date, time or datetime decodes to its ISO 8601 string**, which is FR-2.9 applied to the second format that has temporal types. **An integer outside the signed 64-bit range is refused in both directions**, on decode and on encode, because TOML v1.0.0 requires an error for an integer it cannot carry losslessly. This is the one place FR-4.10's widening does not apply: YAML and JSON leave the range open and TOML does not, and a value Python alone accepts is one no other implementation can read back. **A key is bare only when every character is ASCII `A-Za-z0-9_-`, and quoted otherwise**, because TOML 1.0 bare keys are ASCII while a language's own alphanumeric test may not be: Python's `str.isalnum` answers true for 142,877 code points TOML forbids, and writing one bare produced a document that pack's own loader refused while the save reported success. | [A/D] |
